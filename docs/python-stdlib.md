# Bootstrap standard library

`cpython-bootstrap-stdlib` packages twelve unchanged Python encoding modules from the pinned CPython 3.12.15 submodule. It supplies the encoding package and alias table, ASCII, Latin-1, UTF-8 with its BOM variant, and UTF-16/UTF-32 with explicit endian variants. This is a bootstrap subset for isolated interpreter startup, rather than a complete standard library or a runnable Syncplay runtime.

The exact source/notice inventory and hashes are in `tools/python-stdlib/profile.json`. `stdlib.zip` removes the upstream `Lib/` prefix so Python's ZIP importer can find `encodings`. Entries are stored without compression or generated bytecode, with fixed names, order, timestamps and permissions. `sources.zip` preserves every original source and notice path. The payload also retains the complete upstream LICENSE, README, a selection/modification summary, a per-entry inventory and a bounded import analysis. Original source bytes and CNRI notices are retained unchanged.

The source package requires native interpreter `sys`/`_codecs`, `codecs` and bootstrap ZIP-import interfaces. On Windows the original initializer can additionally try `_winapi` when resolving an ANSI code page. This source review does not clear or distribute those native/frozen implementations. The unchanged alias table also names unselected encodings: their implementations are absent and lookups remain unavailable. Additional standard-library modules, native extensions, Unicode-name/CJK databases, TLS and application dependencies require their own source/license closure.

Build and verify on the matching host:

```bash
python3 tools/dependencies/build.py build --component cpython-bootstrap-stdlib --platform macos-arm64 --cold
python3 tools/dependencies/build.py build --component cpython-bootstrap-stdlib --platform macos-arm64
python3 tools/python-stdlib/stdlib_probe.py --report artifacts/python-stdlib/native.json
```

Use `linux-x64` on Linux and `python` with `windows-x64` on Windows. The existing dependency driver enforces the pinned source export, complete notices, input identities and closed payload on cold and restored-cache paths. Verification regenerates and compares the entire payload, including the ZIP bytes and source mapping; a cached manifest cannot bless changed sources, notices or extra modules.

The native fixture compiles the real [package verifier](python-package.md) and [startup API](python-startup.md). A trusted test inventory is compiled into the disposable native executable. The package scan checks an owned Unicode directory before Python initialization. Same-size corruption, a missing archive and an extra source file must fail before initialization. For the accepted case, the only module search path is the verified owned ZIP. Real codec known answers, incremental/streaming operations, aliases, strict decoding failures, unsupported imports, poisoned environment/current-directory inputs and finalization are exercised. No installed SDK standard-library or extension directory appears on `sys.path`.

This fixture still links an installed developer SDK and uses its builtin/frozen implementations. No SDK runtime or fixture executable is distributed. It does not establish the pinned native interpreter, embedding ABI, complete standard-library compatibility, an authenticated inventory, immutable installation or a safe native loading policy. Those gates, Twisted/TLS trust and headless Syncplay initialization remain required before enabling the runtime. The package verifier records a completed scan and cannot seal files against a hostile writer after verification.
