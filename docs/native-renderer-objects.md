# Native renderer source profile

`skiko-native-objects` is the dependency component for the original Linux renderer. Its `linux-native-runtime-v1` profile builds GN, selected Skia archives, the original AWT JNI translation units and the X11, GLVND, Fontconfig and D-Bus clients from ordinary pinned Git submodules. The component name is retained for compatibility with existing consumers and CI artifacts. Exact source, header, generator, notice, runtime-file and public JNI symbol inventories are in `tools/desktop/profile.json`. macOS uses SwiftUI and Windows uses WPF; common JVM UI bytecode qualification is independent of this native package.

The offline recipe stages each source owner at its declared location. It generates public headers from the original templates, checks the LP64 ABI, and rejects undeclared compiler headers. Xorg protocol generators and macros, XCB and its authentication clients, Xtrans, Xlib and its required extensions, GLVND, FreeType, Expat, zlib, Meson and Fontconfig are explicit source dependencies. Original sources and complete selected grants accompany the package. D-Bus builds its client library with the AFL license alternatives; standalone daemon, CLI and test programs are disabled. Additional upstream build/test/source-only license texts remain preserved with their unchanged sources. GLVND's embedded uthash and Khronos grants are retained separately.

The shared native command, Meson, CMake, compression and Fontconfig configuration helpers live in `tools/native`. VLC uses these same helpers on macOS, Windows and Linux. Native build children use `LC_ALL=C`: inherited locale overrides must not change preprocessing, sorting or legacy X11 alias generation. This build setting does not change the application's user locale. Developer tool provisioning stays outside application payloads.

The renderer uses strict undefined-symbol checking, a public JNI export map and relative `$ORIGIN` library lookup. The package retains the actual linked/imported client closure, the original Skiko dynamic-loader aliases and source-built X11 locale/error/color data. `tools/desktop/platform_data.py` expands the known upstream Compose-table includes while retaining their original rules and grants, and supplies the owned client environment for application launch. Native consumers explicitly set that environment; installed X11 and Fontconfig data must remain available after the build directory is removed. Cache verification checks every retained file, source archive, grant, symbol inventory, ELF architecture, runpath and import. Client libraries remain replaceable regular files. The OS C/compiler ABI, installed GPU vendor drivers and OS/user fonts are explicit external platform services; application X11, GL dispatch, Fontconfig and D-Bus clients are source-owned.

The profile enables text/shaping, SVG, PNG, JPEG, WebP and the selected GPU code. RAW photographic DNG/PIEX decoding is excluded; movies belong to VLC. An independent PNG fixture checks real decoded pixels. A linked consumer loads the original Skiko library, creates, changes and releases an actual Skia path. Negative checks reject missing clients, foreign imports/runpaths, incompatible ELF architecture, symbolic aliases and missing UTF-8 locale data. Build verification moves the installed staging tree out of its configured location before probing, so temporary build resources cannot hide missing package data. An untouched package must still execute its Skia and X11 UTF-8 locale checks after relocation to a path with spaces and Unicode.

```sh
python3 tools/dependencies/build.py prepare --component skiko-native-objects --platform linux-x64
python3 tools/dependencies/build.py build --component skiko-native-objects --platform linux-x64 --cold
```

These native API and decoder checks do not qualify a complete application. JVM distribution, Linux VLC output, current desktop/provider behavior, design fidelity and all six directed macOS/Windows/Linux synchronization cases remain separate requirements. `linux-compose-ui` remains unavailable and `applicationBuildReady` remains false until the complete application graph and actual windows are qualified.
