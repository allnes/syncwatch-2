# Player keyboard and wheel input

The Apache-2.0 Design package owns the platform-neutral input bindings in `player.json`: Space toggles playback, left/right arrows use the configured skip interval, up/down arrows adjust movie volume, M requests movie mute, F requests fullscreen and Escape exits fullscreen. Wheel direction uses the same declared movie-volume step. Continuous seeks and volume changes may repeat; held toggle keys do not oscillate playback, mute or fullscreen.

`PlayerPresentation` resolves each binding against the current native observation and enabled capabilities before emitting the existing player request. Skip requests become bounded seeks. Movie volume remains local and uses the current observed value; no input acknowledges its own request or changes call volume. Modified keys, protected controls and selection popovers retain their native input behavior. An unavailable playback action cannot gain authority through a shortcut.

Native adapters belong to the mounted player and its focused application window. Swift uses an application-local AppKit monitor, C# combines the WPF keyboard message path with an owner HWND wheel hook, and Kotlin post-processes AWT key events and observes wheel input for its current owner. This includes the native video drawable. Hidden or detached players, other windows and modal interactions cannot dispatch playback requests. Detachment removes every owned monitor, hook and listener; callbacks always read the latest presentation.

The shared input corpus covers bounded/configured seeks, local volume limits, invalid observations, revoked capabilities, interruption and completion, repeat suppression, fullscreen-only Escape, protected focus, modifier preservation and nonfinite wheel rejection. Each native implementation executes it on its target OS. Real-window acceptance additionally exercises native video focus, held keys, popovers, fullscreen, local volume isolation, six directed synchronized controls and shutdown.

Platform references: [AppKit local event monitors](https://developer.apple.com/documentation/appkit/nsevent/addlocalmonitorforevents(matching:handler:)), [WPF/Win32 input boundaries](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/wpf-and-win32-interoperation), [WPF keyboard message dispatcher](https://learn.microsoft.com/en-us/dotnet/api/system.windows.interop.componentdispatcher), and [AWT focus-manager dispatch lifetime](https://docs.oracle.com/en/java/javase/21/docs/api/java.desktop/java/awt/KeyboardFocusManager.html).
